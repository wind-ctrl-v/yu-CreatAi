4-3

AI 编辑器执行（LLM + 文件工具）

系统提示词：「你是前端代码编辑器」

AI 编辑器文件工具
执行步骤（必须调用工具）： 1. readDir("src") → 目录读取工具：定位目标 .vue 2. readFile(目标文件) → 文件读取工具：读完整内容 3. modifyFile(替换旧代码) → 文件修改工具：字符串 old→new 精确替换 4. 回复"修改完成"
工具：FileDirReadTool / FileReadTool / FileModifyTool / FileWriteTool / FileDeleteTool
特点：文件级粒度——只改用户点名的地方，其他代码天然不动；路径穿越防护（startsWith 校验）
↓SSE 流式事件：ai_response / tool_request / tool_executed（5 分钟超时 + 错误兜底）

→ URL 不变、内容更新（增量修改不自动重新部署）
⑥ 辅助机制
6

还原 / 不满意 / 换一批 / 埋点

工具栏负反馈
还原（hasEdited 后出现）→ 配合 revert_to_generated 负反馈（-0.20）
不满意 → explicit_dislike（-0.20）｜ 换一批 → reject_suggestion（-0.10）
UNDO 埋点：识别"撤销/回退"类指令 → recordNegativeEvent
记忆压缩：agent.memory.*（80k 字符预算、分层压缩）——长会话不爆上下文
⚠️ 已知缺口：增量编辑不读品牌画像 / 用户偏好 / 设计规范——只靠"现有文件本身就是风格载体"保持一致；如需"带品牌意识的大改"，需在品牌改造方案 P4 中给增量编辑注入品牌摘要。
⑦ 一句话总结

修改链路 = 前端路由分流（选中元素→可视化上下文 / 普通输入→直接修改）→ 增量编辑服务（独立记忆 + 文件工具，readDir → readFile → modifyFile 原地改文件）→ 刷新预览 / 重新部署发布——与全量生成双轨并行，用"局部文件修改"承接拿到 URL 后的所有迭代，只有结构级大改才回落到全量流水线。
