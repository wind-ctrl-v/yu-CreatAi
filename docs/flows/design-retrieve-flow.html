W-3

PGvector 表结构 + HNSW 索引

PGvector
-- 只做相似度检索，业务状态留在 MySQL 权威库 CREATE TABLE design_fingerprint_vector ( fingerprint_id BIGINT UNIQUE, style_profile VARCHAR(32), status VARCHAR(16) DEFAULT 'APPROVED', is_active BOOLEAN DEFAULT true, confidence / priority, embedding vector(1536), source_scope / owner_user_id / project_id / visibility ); CREATE INDEX ... USING hnsw (embedding vector_cosine_ops) WITH (m = 16, ef_construction = 200);
为什么双库？PGvector 的 vector 类型和 <=> 操作符不被 MyBatis-Flex 支持 → 原生 JdbcTemplate 直连 PG；审核/质量/反哺等业务逻辑留在 MySQL，PG 只是向量索引副本。REJECTED/ARCHIVED 时 deactivate() 软删（is_active=false）。
② 读侧：检索流程（多通道降级）
R-1

构造查询文本（两档）

输入：styleProfile + queryTags + requirement + plan + userContext

零 LLM
无个性化（EmbeddingService.buildQueryText）：[设计风格: ecommerce] [需求关键词: 商品, 促销]
有偏好（PersonalizedQueryBuilder.build）：[设计风格: ...] [项目概述: ...] [用户偏好: 深色, 极简] [用户不喜欢: 卡通风] [高频偏好: ...] [高频反感: ...]
★ 查询格式与存储端 buildSemanticText 结构对齐（都是 [标签: 值]），保证同一 embedding 空间可比
↓embeddingModel.embed(queryText) → 1536 维查询向量
R-2

VECTOR_3B：PGvector 向量检索（余弦相似度）

DesignFingerprintVectorRepository.search(queryEmbedding, styleProfile=null, k×3, minSimilarity=0.7, userId)

PGvector原生 SQL
SELECT ..., 1 - (embedding <=> ?::vector) AS similarity FROM design_fingerprint_vector WHERE is_active = true AND status = 'APPROVED' AND (source_scope = 'GLOBAL' OR owner_user_id = ?) -- 权限过滤 AND 1 - (embedding <=> ?::vector) >= 0.7 -- 相似度阈值 ORDER BY embedding <=> ?::vector -- 走 HNSW 索引 LIMIT k*3; -- 粗召回 topK×3
关键点：styleProfile 传 null = 解除硬过滤（全局语义召回，靠阈值兜底，profile 匹配改由排序加分表达）；1 - (embedding <=> ?) = 余弦相似度
R-3

候选组装 + 统一排序精排

向量只负责粗召回，精排交给综合排序

回查完整指纹
组装：逐条 getById(fingerprint_id) 回 MySQL → 投影成 DesignEvidence.Item + softMatchScore（需求关键词与 tone/preferred/layout 子串匹配）+ 同 profile 加分(+2)
排序：priority DESC → confidence DESC → updatedAt DESC → matchScore DESC
个性化排序（开启时）：10 项加权公式
final = 0.25·语义 + 0.15·风格 + 0.15·组件 + 0.10·布局 + 0.10·质量 + 0.15·偏好 − 0.20·反感
↓多样性过滤：EXTRACTED_FINGERPRINT 占比 ≥ 30%

④ 开关与现状
S

配置开关（默认多为关闭）

agent.retrieve.enabled=false ｜ 整体检索开关（关 = 只用静态规范）
agent.retrieve.vector.enabled=false ｜ 3B 向量通道（需 PGvector + Embedding 模型就绪）
agent.retrieve.vector.min-similarity=0.7 ｜ 相似度阈值
agent.retrieve.top-k=2 ｜ 召回条数（≤3）
agent.retrieve.synth.enabled=false ｜ 动态合成兜底
agent.personalization.enabled=true ｜ 个性化查询/排序
现状提醒：projectId 权限字段已建好但检索未按项目过滤（search SQL 无 projectId 条件）——品牌改造方案 P4 将补 PROJECT 级指纹参与召回。
⑤ 一句话总结

指纹入库时：APPROVED 指纹经 语义文本 → 1536 维 Embedding → PGvector（HNSW 索引）双写副本；
生成检索时：需求+偏好 → 查询文本 → 向量化 → 余弦 ≥0.7 粗召回(topK×3) → 综合排序精排 → 多样性过滤 → DesignEvidence 写黑板；
兜底：VECTOR_3B → STRUCTURAL_3A → STATIC_FALLBACK 多通道降级，miss 达阈值触发动态合成——任何时候都有参考证据可用，且召回安全（权限 + APPROVED 门禁）。
