4-2

素材收集 DesignContextAssembler（零 LLM）

串联 5 个 SystemTool，统一装配设计上下文

零 LLM写黑板
① DesignTokenTool（本地 skill/designs/*.md）→ DesignSpec（含 tokenGroups 变量名契约）本地文件
② UserPreferenceTool（业务库）→ UserDesignContext（偏好风格/颜色/布局）MySQL
③ ProjectProfileTool（业务库）→ ProjectBrandContext（品牌名/行业/品牌色）MySQL
④ DesignRetrieveTool（向量库）→ DesignEvidence（参考设计模板/证据，默认开关 agent.retrieve.enabled=false）PGvector
⑤ ContextCompressTool（压缩 + 截断）→ PromptContext（含 fullPrompt，按目标 Agent 裁剪）
⚠️ 数据来源区分：用户偏好 & 品牌画像来自业务库；只有参考模板/证据来自向量库。静态设计规范来自本地 md 文件。
↓黑板：designSpec · userDesignContext · projectBrandContext · designEvidence · promptContext
⚡ 并发执行（Flux.merge）· low_cost 模式则用单遍 PageGenerateAgent

4-4

零 LLM外网搜图

↓进入质检
4-5

规则检查 RuleCriticTool（零 LLM）

确定性检查，结果存 AtomicReference 供后续决策

零 LLM
检查项：P0 核心文件缺失（package.json / index.html / src/main.js / src/App.vue）、占位符残留、同质化模板（Hero+卡片+Footer 机械套用）、card 类名滥用。
↓standard 模式：规则失败才触发 LLM Critic
4-6

LLM 质检 + 定向修复循环 CriticAgent

静态检查 + DesignLintChecker + LLM 评分 → CriticReport → 按 issue.category 路由修复

LLM确定性 lint写黑板
评分：满分 100，P0 每条 -30、P1 -15、P2 -5，≥80 通过；静态规则优先于 LLM（P0 缺失/占位符残留强制 failed）。
修复路由：style→StyleAgent｜code→CoderAgent｜两者→先 Style 后 Coder。
🔁 循环修复：最多 3 轮，把上一轮 issues（含 suggestion）注入回 Coder/Style 做「带着方向重试」；乒乓抑制——检测 Style↔Coder 反复交替 ≥2 次即强制收敛，防死循环。

C

单次流式生成 AiCodeGeneratorFacade

非 Vue 项目或 V2 异常降级时走此链路

Classic

⑧ 数据流一句话总结

自然语言 →（选型）→（策略决策）→ 规划产出需求+计划 → 素材收集装配统一 PromptContext → 代码/样式 Agent 并发流式落盘 → 图片回填 → 规则+LLM 双重质检循环修复 → 构建 → 部署/静态发布 → SSE 全程回推 → URL ，中间所有环节通过线程安全黑板传递结构化中间产物、通过 Flux<AgentEvent> 传递过程事件。
